# SDK patches

All local changes to ReXGlue SDK `v0.10.0` live in `rexglue-v0.10.0.diff`
(applied to `third_party/rexglue-sdk` by `scripts/build.py sdk`).

| # | File | Why |
|---|---|---|
| 1 | thirdparty/CMakeLists.txt | `libmspack/cabextract/mspack/*` are git symlinks; on Windows without `core.symlinks` they check out as one-line text files and `lzxd.c` fails to compile. Point `MSPACK_DIR` at the real `libmspack/libmspack/mspack`. |

Regenerate after editing the SDK: `git -C third_party/rexglue-sdk diff > patches/rexglue-v0.10.0.diff`
| 2 | src/graphics/graphics_system.cpp | Guest vblank thread polled with `Sleep(1)` and caught up late: 60 fps frames spread 13-20 ms (30% > 17.5 ms). Windows: wait on a high-resolution waitable timer until 0.5 ms before each vblank deadline, then spin. Kept only if measurements improve (see NOTES.md). |
| 3 | include/rex/input/mnk/mnk_input_driver.h, src/input/mnk/mnk_input_driver.cpp | Raw 1:1 mouse look: `TakeRawMouseDelta()` returns relative mouse counts accumulated while captured; cvar `mnk_mouse_to_stick` (default true = SDK behaviour) stops feeding the mouse into the right stick. Wet sets it false and applies counts to the camera itself. |
| 4 | include/rex/input/input_system.h, src/input/input_system.cpp | `SetPadStateFilter()`: optional callback applied to each real (non-synthetic) pad's `X_INPUT_STATE` before the per-user merge. Wet uses it for controller button remapping and "press a button" capture. |
| 5 | include/rex/input/mnk/mnk_input_driver.h, src/input/mnk/mnk_input_driver.cpp | Modifier keys: a bare "Shift"/"Control"/"Alt" bind fires while that key is held (SDK could never fire it), and plain keys ignore held modifiers unless the same key is also bound with a modifier prefix somewhere (keeps arrows vs Shift+arrows working, but lets Shift-aim + W-move work). `SetMnkInputSuppressed()`: neutral keyboard/mouse pad while still updating mouse capture, so a menu can free the cursor immediately. |
| 6 | include/rex/perf/counter.h, src/core/perf/counter.cpp, src/graphics/d3d12/pipeline_cache.cpp | Diagnostics: per-frame `pipeline_wait_us` (GPU thread blocked in `EndSubmission` on queued pipeline creation) and `shader_translate_us` counters in the perf CSV; CSV opened share-readable on Windows. |
| 7 | src/graphics/d3d12/pipeline_cache.cpp | `EndSubmission` no longer waits for queued pipeline creation (nor creates pipelines on the GPU thread) when `async_shader_compilation` is on: the command processor already skips draws whose pipeline is not ready, so the wait only stalled frames (measured 100-400 ms per burst of new shaders, 59% of stutter time). Set `--async_shader_compilation=false` for the original blocking behaviour. |
| 8 | src/ui/presenter.cpp, perf counters | `present_pace_hz` (default 60): guest frames are presented on a fixed cadence instead of the moment the guest finishes them; the host presents without vsync, so the guest's render-time variation (+-2 ms measured) otherwise reaches the display as judder. Adds at most one period of latency; re-syncs when behind. `present_interval_us` counter in the perf CSV. Also `cp_fence_wait_us`: time the command processor spends in CheckSubmissionFence waiting for the GPU (diagnoses GPU-queue stalls; with vsync the CSV showed exactly one command_buffer_stall per frame). `shared_mem_upload_bytes` / `shared_mem_upload_ranges` (guest memory uploaded to the GPU shared buffer per frame) and `upload_pool_pages_created` (new upload heap pages), for the draw-translation profile (UploadRanges was 34% of the GPU Commands thread at 1100+ draws). |
| 9 | include/rex/ui/window.h, include/rex/ui/window_sdl.h, src/ui/window_sdl.cpp | `Window::SetExclusiveFullscreenMode(bool)`: exclusive fullscreen at the display mode closest to the desktop mode (SDL3 `SDL_SetWindowFullscreenMode`); the SDK `fullscreen` flag is borderless-desktop only. Needed in the SDK because the runtime DLL has its own SDL3 instance; SDL calls from the exe act on a second, windowless copy. |
| 10 | src/ui/presenter.cpp, src/ui/d3d12/d3d12_presenter.cpp | `host_vsync` (default false): DXGI Present with sync interval 0 and no tearing flag (frames appear at vblank only, a newer frame replaces a queued one, nothing blocks on the display; sync interval 1 coupled the guest to the display and dropped to 43-53 fps); the fixed present cadence (patch 8) is bypassed while it is on. While on, the UI thread paints only when the guest published a frame (a dedicated flag set in the publish path, not the generic paint request that UI drawers re-arm after every paint; 100 ms fallback and surface recovery still paint): continuous overlay repaints otherwise took the refresh slots and the guest ran at 13-33 fps, and later 2 presents per guest frame stalled the shared GPU queue ~11 ms per frame (cp_fence_wait_us). The swap chain is created with `FRAME_LATENCY_WAITABLE_OBJECT` and max frame latency 1 and 4 swap chain buffers (was 3); with vsync on the UI thread waits on that object before painting, because a queued flip-model present otherwise makes the paint wait on the GPU and stalls the guest work behind it on the shared direct queue (measured 12-48 fps). Exposed as "Vertical sync" in the F1 Display tab. |
| 11 | src/graphics/shared_memory.cpp, perf counters | `shared_memory_invalidate_block_log2` (default 18 = 256 KB, the original behaviour): the block a CPU write to GPU-visible memory invalidates in the shared-memory page table. Wet re-uploaded 50-65 MB per frame (2000-2900 ranges, ~34% of the GPU Commands thread) because static vertex data shares 256 KB blocks with per-frame CPU writes. `memory_invalidations` counter (callbacks per frame) measures the access-violation cost of smaller blocks. |
| 12 | include/rex/graphics/d3d12/shared_memory.h, src/graphics/d3d12/shared_memory.cpp | `shared_memory_upload_threads` (default 3; 0 = original): the per-frame guest->upload-buffer memcpy (Wet: ~50 MB in ~2400 ranges per heavy frame, a third of the GPU Commands thread) is split across persistent worker threads plus the command thread; copy commands, page bookkeeping and ordering are unchanged. |
| 13 | include/rex/system/xmemory.h, include/rex/graphics/d3d12/shared_memory.h, src/graphics/d3d12/shared_memory.cpp | `shared_memory_gpu_read_guest` (default true): a D3D12 heap is opened over the guest physical memory (`OpenExistingHeapFromAddress`, falling back to `OpenExistingHeapFromFileMapping` at section offset 0x100000000) and uploads become `CopyBufferRegion` from it, removing the per-frame CPU memcpy (Wet: 45 MB, 3.5 ms at 4 threads, bandwidth-bound) and the upload pool. Page-validity bookkeeping is unchanged; the GPU reads guest memory at execution time, as the console does. |
| 14 | include/rex/graphics/d3d12/deferred_command_list.h, include/rex/graphics/d3d12/command_processor.h, src/graphics/d3d12/command_processor.cpp | `d3d12_async_submit` (default true): each submission's deferred command list is replayed, executed and fence-signalled by a "GPU Submit" worker thread, in order, while the GPU command thread records the next submission; drained at swaps (the presenter paints the frame right after) and at shutdown. The replay measured 5.2 ms of the 15.7 ms GPU-thread frame at 1600-2200 draws (cp_replay_us). Resource lifetimes are already fence-gated, so nothing referenced by a queued list is freed before it executes. |
| 15 | include/rex/graphics/d3d12/texture_cache.h, src/graphics/d3d12/texture_cache.cpp | `d3d12_texture_heap_pool` (default true), `d3d12_texture_heap_size_mb` (64): texture resources are placed in pooled heaps (first-fit free lists, blocks returned on texture destruction, which the cache does only after the last GPU use) instead of one committed resource each. CreateCommittedResource measured 221 us per texture; a streaming burst of 262 textures was a 96 ms frame. Textures larger than a quarter heap stay committed. |
